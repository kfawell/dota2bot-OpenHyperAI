# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Open Hyper AI (OHA)** — a Dota 2 bot AI framework (Steam Workshop ID: 3246316298). Provides intelligent bot behavior, hero-specific builds, dynamic difficulty, and customization for 127 heroes. Written in Lua targeting the Dota 2 VScript bot scripting API.

- **Version**: Tracked in `FunLib/version.lua` (currently `0.7.39`)
- **GitHub**: https://github.com/forest0xia/dota2bot-OpenHyperAI
- **Runtime**: Dota 2 VScript engine (Lua 5.1-compatible, no external dependencies)

## No Build System

There is no build step, linter, or test runner. Lua files are loaded directly by the Dota 2 engine at runtime. Files in `ts_libs/` are generated by TypeScriptToLua — do not edit those directly.

To test changes: launch Dota 2, create a lobby with cheats enabled, and play-test. For FretBots mode, run `script_reload_code bots/Buff/buff` in the Dota 2 console.

## Two Runtime Contexts (Critical)

**Bot Script Context** — `bot_generic.lua`, `hero_selection.lua`, `mode_*.lua`, `BotLib/`, `FunLib/`. Has `GetBot()`, `GetScriptDirectory()`, `dofile()`, `require()` with script-relative paths.

**VScript Game Context** — `FretBots.lua`, `FretBots/*.lua`, `Buff/*.lua`. Has `GameRules`, `ListenToGameEvent()`, `CreateTimer()`. Uses `require 'bots.FretBots.ModuleName'` (dot-path notation).

**Do not mix APIs between contexts.** They share no global state.

## Architecture & Execution Flow

### Entry Points (called by Dota 2 engine)

1. **`hero_selection.lua`** — Hero picking phase. Matchup-aware picking, weak hero caps, Captain's Mode support. Reads `Customize/general.lua` for user preferences.

2. **`bot_generic.lua`** — Main per-bot think loop (every frame). Loads hero config from `BotLib/hero_*.lua` via `dofile()`, delegates ability leveling and minion thinking.

3. **`ability_item_usage_generic.lua`** (232KB) — Per-frame ability/item casting decisions. The largest file. Loads hero config, calls `X.SkillsComplement()` for hero-specific ability logic. Contains special-case handling for heroes with non-standard ability layouts (e.g., Kez stance-switching).

4. **`item_purchase_generic.lua`** — Gold spending with component tracking. Breaks target items into sub-components, prevents over-buying via `currBuyingRequiredCounts` map.

5. **`mode_*.lua`** (~20 files) — Behavioral modes competing for activation via desire system.

6. **`FretBots.lua`** — Optional enhanced difficulty system (VScript context). Initializes 33+ modules from `FretBots/` via game state listener on `DOTA_GAMERULES_STATE_PRE_GAME`.

### Mode File Interface

Every `mode_*.lua` file runs in global scope and must export these functions:

```lua
function GetDesire()    -- REQUIRED. Returns 0.0–1.0 (float). Called every frame.
function Think()        -- Called every frame when this mode is the highest-desire active mode.
function OnStart()      -- Called once when this mode activates. Optional.
function OnEnd()        -- Called once when this mode deactivates. Optional.
```

The engine calls `GetDesire()` on all modes each frame and activates the highest one. Modes use `BOT_MODE_DESIRE_NONE`, `BOT_MODE_DESIRE_MODERATE`, `BOT_MODE_DESIRE_ABSOLUTE` constants, or fractional values (0.2, 0.72, 0.95) for fine-tuning.

**Common patterns in modes:**
- Entry validation: `if bot == nil or bot:IsInvulnerable() or not bot:IsHero() or bot:IsIllusion() then return end`
- Desire caching: `J.Utils.GetCachedVars(key, ttlSeconds)` / `J.Utils.SetCachedVars(key, value)` to reduce per-frame computation
- Override delegation: Some modes check for hero-specific overrides in `FunLib/override_generic/`

### Hero Config Files (`BotLib/hero_*.lua`)

Every hero file returns table `X` with this structure:

```lua
local X = {}
local J = require(GetScriptDirectory()..'/FunLib/jmz_func')
local Minion = dofile(GetScriptDirectory()..'/FunLib/aba_minion')

-- TALENT TREE: {left_weight, right_weight} per tier. 10 = prefer, 0 = avoid.
local tTalentTreeList = {
  ['t25'] = {10, 0}, ['t20'] = {0, 10}, ['t15'] = {10, 0}, ['t10'] = {0, 10},
}

-- ABILITY BUILD: numbers 1-5 = ability slots (Q,W,E,D,F), 6 = ultimate (R).
-- One sub-table per position variant.
local tAllAbilityBuildList = {
  {1,2,1,3,1,6,2,2,2,1,6,3,3,3,6},  -- 15 entries for levels 1-15
}

-- ITEM BUILDS: keyed by role string 'pos_1' through 'pos_5'.
local sRoleItemsBuyList = {}
sRoleItemsBuyList['pos_1'] = {"item_tango", "item_power_treads", "item_bfury", ...}
sRoleItemsBuyList['pos_3'] = { ... }
-- Positions can alias: sRoleItemsBuyList['pos_2'] = sRoleItemsBuyList['pos_1']

X['sBuyList'] = sRoleItemsBuyList[sRole]
X['sSellList'] = {"item_magic_wand", ...}

-- PvN mode override
if J.Role.IsPvNMode() or J.Role.IsAllShadow() then
  X['sBuyList'], X['sSellList'] = {'PvN_heroname'}, {}
end

-- Apply user customizations (from Customize/hero/*)
nAbilityBuildList, nTalentBuildList, X['sBuyList'], X['sSellList'] =
  J.SetUserHeroInit(nAbilityBuildList, nTalentBuildList, X['sBuyList'], X['sSellList'])

X['sSkillList'] = J.Skill.GetSkillList(sAbilityList, nAbilityBuildList, sTalentList, nTalentBuildList)
X['bDeafaultAbility'] = false  -- NOTE: "Deafault" is intentional typo, keep for compatibility
X['bDeafaultItem'] = false     -- false = custom logic, true = default Dota 2 AI

function X.MinionThink(hMinionUnit) ... end     -- Summon/illusion AI
function X.SkillsComplement() ... end           -- Hero-specific ability casting (called by ability_item_usage_generic.lua)
-- Per-ability functions: X.ConsiderAbilityName() returning (desire, target/location)

return X
```

### Key Directories

- **`BotLib/`** — 127 hero config files (`hero_*.lua`), one per hero
- **`FunLib/`** — Core utility libraries. `jmz_func.lua` (173KB) is the master library imported as `J` everywhere. Sub-modules: `aba_site.lua` (map/positioning), `aba_item.lua` (purchasing), `aba_role.lua` (pos 1-5 classification), `aba_skill.lua` (ability upgrades), `aba_matchups.lua` (82KB hero-vs-hero data), `aba_chat.lua` (chat/communication), `aba_minion.lua` (summon AI), `localization.lua` (en/zh/ru/ja)
- **`FretBots/`** — Enhanced difficulty modules (VScript context). `Settings.lua` handles difficulty voting (0-10), `DynamicDifficulty.lua` for adaptive scaling
- **`Customize/`** — User-facing config: `general.lua` for global settings, `hero/*.lua` for per-hero overrides
- **`Buff/`** — Standalone GPM/XPM boost (VScript context, manual activation via `script_reload_code bots/Buff/buff`). Core files: `GPM.lua`, `Experience.lua`, `Helper.lua`
- **`FunLib/rubick_hero/`** — Rubick spell-steal behavior per hero (e.g., `axe.lua`, `crystal_maiden.lua`). Defines how stolen abilities are used
- **`FunLib/override_generic/`** — Per-hero mode overrides (e.g., `mode_attack_generic.lua`, `mode_laning_generic.lua`). Checked by modes before default logic
- **`Install-to-vscript/`** — Installation helper scripts (`.bat`/`.sh`) for copying the workshop to the local vscripts folder
- **`ts_libs/`** — TypeScriptToLua generated code. **Do not edit manually.**

## Key J.* Functions (jmz_func.lua)

`J` is the universal utility library. Key categories:

**Action guards** — Call before any bot action:
- `J.CanNotUseAction(bot)` — stunned, channeling, etc.
- `J.CanNotUseAbility(bot)` — silenced, hexed, etc.
- `J.IsTryingtoUseAbility(bot)` — mid-cast/channeling

**Unit validation:**
- `J.IsValid(unit)`, `J.IsValidHero(unit)`, `J.IsValidTarget(target)`, `J.CanBeAttacked(target)`

**Proximity queries:**
- `J.GetAlliesNearLoc(loc, radius)`, `J.GetEnemiesNearLoc(loc, radius)`
- `J.GetAroundTargetEnemyHeroCount(target, radius)`

**State queries:**
- `J.GetHP(bot)`, `J.GetMP(bot)` — health/mana as 0.0-1.0 fraction
- `J.IsCore(bot)` — pos 1-3
- `J.GetPosition(bot)` — returns 1-5
- `J.IsInLaningPhase()` — game time < ~10 minutes

**Combat helpers:**
- `J.GetProperTarget(bot)` — best attack target
- `J.WillKillTarget(target, damage, damageType, delay)`
- `J.HasMovableUndyingModifier(unit, delay)` — checks for Borrowed Time, Shallow Grave, etc.

**Sub-modules accessed via J:**
- `J.Site` — map awareness, lane assignment
- `J.Item` — item management; `J.Item.GetRoleItemsBuyList(bot)` returns role string
- `J.Role` — role detection; `J.Role.IsPvNMode()`, `J.Role.IsAllShadow()`
- `J.Skill` — ability paths; `J.Skill.GetSkillList()`, `J.Skill.GetRandomBuild()`, `J.Skill.GetTalentBuild()`
- `J.Utils` — `GetCachedVars(key, ttl)`, `SetCachedVars(key, val)`

## Customization System

### Global Config (`Customize/general.lua`)

Key fields: `Enable`, `Localization` (en/zh/ru/ja), `Ban` (hero list), `Radiant_Heros`/`Dire_Heros`, `Radiant_Names`/`Dire_Names`, `Allow_Repeated_Heroes`, `Weak_Hero_Cap`, `Allow_Trash_Talk`, `Trash_Talk_Level` (1-2), `Force_Group_Push_Level` (1-3), `ThinkLess` (0-10 CPU reduction), `Fretbots` sub-table (Default_Difficulty 0-10, Allow_To_Vote, etc.).

### Load Order

`FunLib/custom_loader.lua` tries `game/Customize/general` (user's local vscripts folder) first, falling back to the workshop's `Customize/general.lua`. This lets users override without modifying workshop files.

### Per-Hero Overrides (`Customize/hero/[heroname].lua`)

```lua
return {
  Enable = true,
  AbilityUpgrade = {1,2,1,3,1,6,2,2,2,1,6,3,3,3,6},
  Talent = {['t25']={10,0}, ['t20']={0,10}, ['t15']={10,0}, ['t10']={0,10}},
  PurchaseList = {"item_tango", "item_power_treads", ...},
  SellList = {"item_magic_wand"},
}
```

## FretBots Module Pattern

Modules are `require`'d by `FretBots.lua` at startup. They self-initialize when called:

```lua
-- FretBots.lua registers a game state listener:
Utilities:RegsiterGameStateListener(FretBots, 'Initialize', DOTA_GAMERULES_STATE_PRE_GAME)

-- FretBots:Initialize() then calls each module's :Initialize()
-- Modules create timers via Timers:CreateTimer(name, {endTime=1, callback=fn})
-- Return 1 from callback to repeat, nil to stop
```

Key globals: `Settings.difficulty` (0-10), `Settings.difficultyScale`, `Flags.isFretBotsInitialized`.

Chat commands: `/difficulty 7`, `/stats kills`, `/getroles`, `/set gpm.offset 100`.

## Conventions

### Variable Naming

- `J` — always `jmz_func.lua`
- `X` — hero config table from `BotLib/hero_*.lua`
- `s` prefix — string, `t` prefix — table, `n` prefix — number, `b` prefix — boolean
- `aba_` prefix — FunLib sub-modules
- `pos_1` through `pos_5` — Dota 2 farm priority positions
- `bDeafaultAbility`/`bDeafaultItem` — "Deafault" is a known typo, **preserve it** for backward compatibility

### Hero/Item Internal Names

Use Dota 2 internal names: `npc_dota_hero_antimage`, `npc_dota_hero_crystal_maiden`. Items use `item_` prefix: `item_bfury`, `item_manta`. Reference: [heroes](https://github.com/forest0xia/dota2bot-OpenHyperAI/discussions/71), [items](https://github.com/forest0xia/dota2bot-OpenHyperAI/discussions/73).

### Hero Selection — Weak Hero System

A `WeakHeroes` list tracks underpowered/buggy heroes. `Customize.Weak_Hero_Cap` limits how many can be picked per team. Penalty is exponential (`base^weakPicked`), making multiple weak picks increasingly unlikely.
